# مثال عملي: نظام الموافقات

## 📋 السيناريو

مستخدم عادي يريد تنفيذ أمر على النظام، لكن الأمر يتطلب موافقة من المشرف.

---

## 🔄 الخطوات العملية

### الخطوة 1️⃣: المستخدم يطلب تنفيذ أمر

**الطريقة 1: من خلال Agent Console**
```
المستخدم: "اعرض الملفات في المجلد الحالي"
```

**الطريقة 2: من خلال صفحة Tools**
1. يذهب المستخدم إلى صفحة **Tools**
2. يكتب الأمر في حقل "Run Shell": `ls -la`
3. يضغط على زر **"⚡ Execute"**

---

### الخطوة 2️⃣: النظام يتحقق من الإعدادات

النظام يفحص:
- ✅ هل `run_shell` مفعّل؟ (`allow_shell: true`)
- ✅ هل `run_shell` يتطلب موافقة؟ (`require_approval: ["run_shell"]`)
- ❌ هل المستخدم لديه صلاحية الموافقة؟ (Admin/DevOps فقط)

**النتيجة:** المستخدم ليس لديه صلاحية، يتم إنشاء طلب موافقة

---

### الخطوة 3️⃣: إنشاء طلب الموافقة

**الرد للمستخدم:**
```json
{
  "status": "pending",
  "action_id": "action_1234567890",
  "message": "Action requires approval"
}
```

**يظهر للمستخدم:**
```
⚠️ هذا الأمر يتطلب موافقة من المشرف
طلب الموافقة رقم: action_1234567890
```

**يتم حفظ الطلب في قاعدة البيانات:**
```json
{
  "id": "action_1234567890",
  "user_email": "user@example.com",
  "tool_name": "run_shell",
  "tool_args": {
    "cmd": "ls -la"
  },
  "reason": "Requires approval",
  "status": "pending",
  "created_at": "2024-11-16T12:00:00Z"
}
```

---

### الخطوة 4️⃣: المشرف يرى الطلب

**المشرف (Admin أو DevOps):**
1. يذهب إلى صفحة **Approvals** من القائمة الجانبية
2. يرى الطلب في قسم **"⏳ Pending (1)"**

**معلومات الطلب:**
```
🔔 run_shell - user@example.com

Arguments:
{
  "cmd": "ls -la"
}

Reason: Requires approval

Created: 11/16/2024, 12:00:00 PM

[✅ Approve]  [❌ Reject]
```

---

### الخطوة 5️⃣: المشرف يقرر

#### ✅ الخيار 1: الموافقة

**المشرف يضغط على زر "✅ Approve"**

**ما يحدث:**
1. ✅ يتم تحديث حالة الطلب إلى `approved`
2. ✅ يتم تنفيذ الأمر: `ls -la`
3. ✅ يتم حفظ النتيجة
4. ✅ يتم إرسال إشعار للمستخدم

**النتيجة في صفحة Approvals:**
```
✅ run_shell - user@example.com (approved)

Approved by admin@example.com at 11/16/2024, 12:05:00 PM

Execution Result:
total 48
drwxr-xr-x 2 user user 4096 Nov 16 12:00 .
drwxr-xr-x 5 user user 4096 Nov 16 11:00 ..
-rw-r--r-- 1 user user 1024 Nov 16 11:30 file1.txt
-rw-r--r-- 1 user user 2048 Nov 16 11:35 file2.txt
```

**المستخدم يرى النتيجة:**
- في Agent Console: "تم تنفيذ الأمر بنجاح"
- في Tools Page: النتيجة تظهر في output area

---

#### ❌ الخيار 2: الرفض

**المشرف يضغط على زر "❌ Reject"**

**ما يحدث:**
1. يطلب النظام سبب الرفض (اختياري)
2. المشرف يكتب: "الأمر غير مسموح به لأسباب أمنية"
3. ✅ يتم تحديث حالة الطلب إلى `rejected`
4. ✅ يتم حفظ سبب الرفض
5. ✅ يتم إرسال إشعار للمستخدم

**النتيجة في صفحة Approvals:**
```
❌ run_shell - user@example.com (rejected)

Rejected by admin@example.com at 11/16/2024, 12:05:00 PM

Reason: الأمر غير مسموح به لأسباب أمنية
```

**المستخدم يرى:**
```
❌ تم رفض طلبك
السبب: الأمر غير مسموح به لأسباب أمنية
```

## 📝 مثال كامل: حذف ملف

### 1. المستخدم يطلب:
```
المستخدم: "احذف الملف test.txt"
```

### 2. Agent يحدد الأمر:
```bash
rm test.txt
```

### 3. النظام يتحقق:
- ✅ `allow_shell: true`
- ✅ `require_approval: ["run_shell"]`
- ❌ المستخدم ليس Admin/DevOps

### 4. يتم إنشاء طلب موافقة:
```json
{
  "id": "action_7890123456",
  "user_email": "developer@example.com",
  "tool_name": "run_shell",
  "tool_args": {"cmd": "rm test.txt"},
  "status": "pending",
  "created_at": "2024-11-16T12:10:00Z"
}
```

### 5. المشرف يرى الطلب:
```
⏳ Pending Actions (1)

🔔 run_shell - developer@example.com

Arguments:
{
  "cmd": "rm test.txt"
}

Created: 11/16/2024, 12:10:00 PM

[✅ Approve]  [❌ Reject]
```

### 6. المشرف يوافق:
- يضغط على "✅ Approve"
- يتم تنفيذ الأمر: `rm test.txt`
- النتيجة: "تم حذف الملف بنجاح"

### 7. المستخدم يرى النتيجة:
```
✅ تم تنفيذ الأمر بنجاح
تم حذف الملف test.txt
```

## 🔧 الإعدادات

في صفحة **Settings**، يمكنك التحكم في:

### 1. Allow Shell
تفعيل/تعطيل تنفيذ الأوامر:
```json
{
  "allow_shell": true  // أو false
}
```

### 2. Require Approval
قائمة الأدوات التي تتطلب موافقة:
```json
{
  "require_approval": ["run_shell", "read_file"]
}
```

**ملاحظة:** إذا كان `run_shell` في قائمة `require_approval`، فجميع أوامر shell تحتاج موافقة.

---

## 👥 الأدوار والصلاحيات

| الدور | يمكنه | لا يمكنه |
|------|-------|---------|
| **Admin** | ✅ الموافقة/الرفض على جميع الطلبات<br>✅ تنفيذ الأوامر مباشرة | - |
| **DevOps** | ✅ الموافقة/الرفض على جميع الطلبات<br>✅ تنفيذ الأوامر مباشرة | - |
| **Developer** | ✅ إنشاء طلبات موافقة | ❌ الموافقة/الرفض |
| **Viewer** | ✅ عرض البيانات فقط | ❌ إنشاء طلبات موافقة<br>❌ الموافقة/الرفض |

---

## 🔐 الأمان

1. ✅ جميع الطلبات تُسجّل في قاعدة البيانات
2. ✅ يمكن تتبع من وافق/رفض ومتى
3. ✅ النتائج تُحفظ للتدقيق
4. ✅ فقط Admin/DevOps يمكنهم الموافقة/الرفض
5. ✅ يمكن رؤية تاريخ جميع الطلبات في صفحة Approvals

## 📊 تدفق العملية

```
المستخدم يطلب أمر
        ↓
النظام يتحقق من الإعدادات
        ↓
هل يتطلب موافقة؟
   ↙        ↘
  لا          نعم
  ↓           ↓
تنفيذ مباشر   إنشاء طلب موافقة
              ↓
        المشرف يرى الطلب
              ↓
        يقرر: موافقة أو رفض
         ↙            ↘
      موافقة         رفض
        ↓              ↓
   تنفيذ الأمر    إرسال إشعار بالرفض
        ↓
   إرسال النتيجة للمستخدم
```

---

## 💡 نصائح

1. **للمستخدمين:**
   - إذا رأيت رسالة "Action requires approval"، انتظر موافقة المشرف
   - يمكنك متابعة حالة طلبك في صفحة Approvals

2. **للمشرفين:**
   - راجع الطلبات بانتظام
   - ارفض الطلبات المشبوهة
   - اكتب سبب واضح عند الرفض

3. **للمطورين:**
   - يمكنك إضافة أدوات جديدة تتطلب موافقة
   - أضف اسم الأداة إلى `require_approval` في الإعدادات
