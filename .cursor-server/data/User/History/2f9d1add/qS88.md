## ⚠️ المشاكل الحرجة (Critical Issues)

### 1. **تكرار دالة `run()` في security_scan.py** 🔴
```python
# السطر 1151
def run(action: str = "scan_repo", **kwargs) -> Dict[str, Any]:
    ...

# السطر 1842 (مكرر!)
def run(action: str = "scan_repo", **kwargs) -> Dict[str, Any]:
    ...
```
**المشكلة**: دالة مكررة - الثانية ستحل محل الأولى
**الحل**: حذف إحداهما أو دمجها

### 2. **security_scan.py كبير جداً** 🔴
- **الحجم**: 1880 سطر
- **المشكلة**: صعب الصيانة، بطيء التحميل
- **الحل**: تقسيمه إلى:
  ```
  security_scan/
  ├── __init__.py
  ├── repo_scanner.py
  ├── network_scanner.py
  ├── docker_scanner.py
  ├── vulnerability_scanner.py
  └── base.py (shared utilities)
  ```

### 3. **pending_actions.py يستخدم مسارات مباشرة** 🟡
```python
PENDING_ACTIONS_FILE = "memory/pending_actions.json"  # ❌
```

**المشكلة**: لا يستخدم `resolve_path`
**الحل**: استخدام `resolve_path("memory/pending_actions.json")`

## 🟡 مشاكل متوسطة (Medium Issues)

### 5. **لا يوجد Abstraction Layer**
- Tools تستدعى مباشرة من API
- **المشكلة**: صعب التغيير/الاختبار
- **الحل المقترح**:
  ```python
  # app/services/security_service.py
  class SecurityService:
      def scan_repo(self, path, max_files):
          return scan_repo(path, max_files)
  ```

### 6. **Error Handling غير موحد**
- كل endpoint يعالج الأخطاء بطريقة مختلفة
- **الحل**: Middleware موحد للـ error handling

### 7. **Logging غير موحد**
- بعض الملفات تستخدم `print()`
- بعضها يستخدم `logging`
- **الحل**: Logger موحد في `app/utils/logger.py`

### 8. **Type Hints غير كاملة**
- بعض الدوال بدون type hints
- **الحل**: إضافة type hints لجميع الدوال
