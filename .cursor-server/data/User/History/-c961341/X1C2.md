# 🔧 Font 403 Error Fix

## المشكلة
```
GET http://crm.bankid-sy.com/__nextjs_font/geist-latin.woff2 403 (Forbidden)
```

## السبب
Next.js 13+ يستخدم مسار `/__nextjs_font/` للخطوط، لكن NGINX config لم يكن يغطي هذا المسار.

## الحل ✅

تم إضافة location block خاص لـ `__nextjs_font` في كلا الملفين:

1. **nginx-crm-complete.conf** - للـ CRM
2. **nginx-aaa.conf** - للـ AAA

### التغييرات:

```nginx
# Next.js Font files (must be before / location)
location /__nextjs_font {
    proxy_pass http://crm_frontend;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    add_header Access-Control-Allow-Origin *;
    add_header Access-Control-Allow-Methods "GET, OPTIONS";
    add_header Access-Control-Allow-Headers "Range";
    add_header Cache-Control "public, max-age=31536000, immutable";
    expires 1y;
}
```

## 📋 خطوات التطبيق

### 1. تحديث NGINX Configs

```bash
# للـ CRM
sudo cp nginx-crm-complete.conf /etc/nginx/sites-available/crm.bankid-sy.com

# للـ AAA
sudo cp nginx-aaa.conf /etc/nginx/sites-available/aaa.bankid-sy.com
```

### 2. اختبار وإعادة تحميل

```bash
# اختبار التكوين
sudo nginx -t

# إذا كان كل شيء صحيح
sudo systemctl reload nginx
```

### 3. التحقق

بعد إعادة تحميل NGINX:
1. افتح `https://crm.bankid-sy.com`
2. افتح Developer Console (F12)
3. تحقق من Network tab - يجب ألا يكون هناك 403 errors للخطوط

## 🔍 ملاحظات مهمة

1. **ترتيب Location Blocks**: 
   - `location /__nextjs_font` يجب أن يكون **قبل** `location /`
   - NGINX يطابق location blocks بالترتيب

2. **CORS Headers**:
   - `Access-Control-Allow-Origin *` - يسمح بتحميل الخطوط من أي domain
   - `Access-Control-Allow-Headers "Range"` - مهم لـ font loading

3. **Caching**:
   - الخطوط يتم cache لمدة سنة
   - هذا يحسن الأداء
